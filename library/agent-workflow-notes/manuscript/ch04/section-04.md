# 재시도, 중단 조건, 로그는 왜 설계에 들어가야 하나요?

자동화가 잘 돌아가는 장면만 생각하면 실무 시스템은 금방 무너집니다. 실제로는 외부 도구가 실패하고, 입력이 비어 있고, 네트워크가 끊기고, 예상 못 한 예외가 계속 생깁니다. 그래서 재시도와 중단 조건, 로그는 부가 기능이 아니라 운영의 기본 장치입니다.

데모 수준 자동화와 실무 자동화의 가장 큰 차이도 여기에 있습니다. 결과가 그럴듯한가보다, 실패했을 때 어떻게 멈추고 어떻게 되짚을 수 있는가가 훨씬 더 중요해지는 순간이 옵니다.

## 재시도는 만능이 아니라 조건부 장치입니다

일시적인 네트워크 오류처럼 다시 해 보면 되는 문제도 있지만, 입력 자체가 잘못된 경우까지 반복 호출하면 오히려 비용과 혼란만 커집니다. 그래서 어떤 오류에서만 다시 시도할지, 몇 번까지 허용할지, 이후에는 누구에게 넘길지를 정해야 합니다.

재시도는 만능이 아니라 조건부 장치입니다가 중요해지는 순간은 외부 호출 실패나 형식 오류처럼 작은 문제가 반복될 수 있는 순간입니다. 초반에는 중단 조건이 없으면 비용과 오류가 조용히 커지기 쉽습니다. 워크플로우를 짤 때는 어떤 오류는 재시도하고 어떤 오류는 즉시 멈출지 명확히 나눠야 합니다. 운영 품질은 성공 횟수보다 실패를 얼마나 설명 가능하게 남기느냐에서 드러납니다.

## 중단 조건이 없으면 작은 오류가 커집니다

필수 필드가 비어 있을 때, 권한이 없을 때, 자료가 충분하지 않을 때 다음 단계로 넘어가지 않게 만드는 규칙이 필요합니다. 이런 조건이 없으면 에이전트는 정보가 부족해도 계속 앞으로 나아가 더 큰 오류를 만듭니다. 잘 멈추는 자동화가 결국 잘 작동하는 자동화입니다.

실무 자동화에서는 외부 호출 실패나 형식 오류처럼 작은 문제가 반복될 수 있는 순간입니다. 재시도를 만능 해결책처럼 붙이면 같은 실수를 더 빨리 반복할 수 있습니다. 그래서 설계 단계에서 어떤 오류는 재시도하고 어떤 오류는 즉시 멈출지 명확히 나눠야 합니다. 운영 품질은 성공 횟수보다 실패를 얼마나 설명 가능하게 남기느냐에서 드러납니다.

## 로그는 개선의 시작점입니다

어떤 입력이 들어왔고, 어느 단계에서 도구가 실패했고, 어떤 결과가 사람 검토에서 자주 수정됐는지 남아 있어야 품질 개선이 가능합니다. 기록이 없으면 자동화는 그날그날 감으로 고치는 시스템이 됩니다. 운영 가능한 자동화는 반드시 되짚을 흔적을 남깁니다.

재시도, 중단 조건, 로그는 왜 설계에 들어가야 하나요를 길게 운영하려면 실패 기록이 있어야 다음 개선이 가능한 운영 구간에서 차이가 생깁니다. 반대로 중단 조건이 없으면 비용과 오류가 조용히 커지기 쉽습니다. 그래서 중간 단계에서 어떤 오류는 재시도하고 어떤 오류는 즉시 멈출지 명확히 나눠야 합니다. 운영 품질은 성공 횟수보다 실패를 얼마나 설명 가능하게 남기느냐에서 드러납니다.

## 잘 멈추는 시스템이 결국 오래 갑니다

자동화는 끝까지 가는 힘보다, 적절한 순간 멈추는 힘이 더 중요할 때가 많습니다. 자료가 부족하거나, 권한이 없거나, 외부 도구가 실패했을 때 멈추지 못하면 작은 오류가 큰 문제로 커집니다. 중단 조건을 설계한다는 것은 자동화를 약하게 만드는 것이 아니라, 더 오래 버티게 만드는 일입니다.

재시도, 중단 조건, 로그는 왜 설계에 들어가야 하나요를 운영 관점에서 보면 외부 호출 실패나 형식 오류처럼 작은 문제가 반복될 수 있는 순간입니다. 흔한 오해는 로그 없이 실패를 복기하면 결국 사람 기억과 감정에 의존하게 됩니다. 실제로는 어떤 오류는 재시도하고 어떤 오류는 즉시 멈출지 명확히 나눠야 합니다. 운영 품질은 성공 횟수보다 실패를 얼마나 설명 가능하게 남기느냐에서 드러납니다.

## 로그는 사람을 탓하지 않게 해 줍니다

기록이 없으면 실패 원인을 사람 기억에 의존하게 됩니다. 그러면 개선도 감정적으로 흘러가기 쉽습니다. 반대로 어느 단계에서 무엇이 실패했는지가 남아 있으면 자동화 문제를 개인의 실수보다 구조의 문제로 볼 수 있게 됩니다.

재시도, 중단 조건, 로그는 왜 설계에 들어가야 하나요를 운영 관점에서 보면 중간 단계에서 멈추고 다시 시도해야 전체 품질을 지킬 수 있는 장면입니다. 흔한 오해는 중단 조건이 없으면 비용과 오류가 조용히 커지기 쉽습니다. 실제로는 시도 횟수, 간격, 중단 기준, 핵심 입력과 출력 로그를 함께 설계해야 합니다. 재시도와 로그 구조가 있으면 실패도 다음 개선의 재료가 됩니다.

정리하면 재시도와 중단 조건, 로그는 실패를 숨기는 장치가 아니라 실패를 작게 만들고 다음 개선으로 연결하는 장치입니다. 운영 가능한 자동화는 늘 이 세 가지를 함께 생각합니다.
