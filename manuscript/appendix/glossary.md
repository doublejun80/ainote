# 부록. 핵심 용어집

이 용어집은 본문을 읽다가 뜻이 흐려진 단어를 빠르게 다시 잡기 위한 공간입니다. 여기의 설명은 짧지만, 가능한 한 초보자의 질문 순서에 맞추었습니다. 먼저 "이 말은 대체 무엇인가"를 설명하고, 이어서 "어디서 헷갈리는가"를 짚는 방식으로 정리했습니다.

용어집은 본문을 대신하지는 않습니다. 대신 본문으로 다시 돌아가기 위한 발판 역할을 합니다. 단어 하나가 막히면 전체 흐름이 멈추기 쉬우므로, 여기서는 완벽한 정의보다 방향을 잃지 않게 하는 설명을 우선했습니다.

## 1. 개발을 처음 시작할 때 자주 만나는 말

### 알고리즘

뜻: 문제를 해결하는 절차와 규칙입니다. 같은 문제라도 어떤 알고리즘을 쓰느냐에 따라 속도와 메모리 사용량이 크게 달라집니다.

헷갈리기 쉬운 점: 코드를 많이 쓰는 것과 알고리즘을 잘 짜는 것은 다릅니다. 알고리즘은 문법보다 문제 해결 순서에 더 가깝습니다.

### 자료 구조

뜻: 데이터를 어떤 모양으로 저장하고 다룰지 정한 방식입니다. 배열, 연결 리스트, 해시 맵, 트리 같은 것이 여기에 들어갑니다.

헷갈리기 쉬운 점: 알고리즘이 요리 순서라면 자료 구조는 재료를 담는 그릇에 가깝습니다. 둘은 함께 움직입니다.

### 프로그래밍 언어

뜻: 사람이 컴퓨터에게 일을 시키기 위해 쓰는 형식화된 언어입니다. C, Java, Python, JavaScript 같은 이름이 여기에 해당합니다.

헷갈리기 쉬운 점: 언어마다 문법만 다른 것이 아니라 잘 맞는 문제 영역과 생태계도 다릅니다.

### 프레임워크

뜻: 자주 쓰는 구조와 규칙을 미리 마련해 둔 작업 틀입니다. 개발 속도를 올려 주지만 그 틀의 사고방식도 함께 받아들이게 됩니다.

헷갈리기 쉬운 점: 프레임워크는 언어를 대체하지 않습니다. 언어 위에 올라가는 구조화 도구입니다.

### 라이브러리

뜻: 필요한 기능을 가져다 쓰도록 묶어 둔 코드 모음입니다.

헷갈리기 쉬운 점: 프레임워크가 흐름을 먼저 정해 두는 경우가 많다면, 라이브러리는 필요한 순간에 내가 호출해서 쓰는 경우가 많습니다.

### 런타임

뜻: 코드가 실제로 실행되는 환경입니다. 브라우저, JVM, Node.js 같은 말이 런타임과 관련됩니다.

헷갈리기 쉬운 점: 언어를 안다고 끝이 아니라, 그 언어가 어디에서 실행되는지도 알아야 문제를 해석할 수 있습니다.

### 컴파일러

뜻: 사람이 쓴 코드를 기계가 실행하기 쉬운 형태로 바꾸는 프로그램입니다.

헷갈리기 쉬운 점: 컴파일된 언어라고 해서 무조건 빠르고, 인터프리터 언어라고 해서 무조건 느린 것은 아닙니다.

### 인터프리터

뜻: 코드를 줄 단위 또는 실행 시점에 해석하면서 동작시키는 방식 또는 그 프로그램입니다.

헷갈리기 쉬운 점: 실행이 편하다는 장점이 있지만, 실제 성능은 런타임 최적화와 구현 방식에 따라 다양합니다.

### IDE

뜻: 코드 작성, 실행, 디버깅, 탐색을 한곳에서 돕는 개발 도구입니다.

헷갈리기 쉬운 점: IDE를 잘 쓴다고 개발을 다 아는 것은 아니지만, 좋은 도구는 학습 속도를 크게 올려 줍니다.

### CLI

뜻: 명령줄 인터페이스입니다. 마우스 대신 텍스트 명령으로 프로그램을 다루는 방식입니다.

헷갈리기 쉬운 점: 처음엔 낯설지만 자동화와 반복 작업에서 매우 강력합니다.

### Git

뜻: 코드 변경 이력을 기록하고 여러 사람이 협업할 수 있게 돕는 버전 관리 시스템입니다.

헷갈리기 쉬운 점: GitHub는 Git 저장소를 올려 협업하기 쉬운 서비스이고, Git 자체와는 구분됩니다.

## 2. 코드 구조와 설계에서 자주 만나는 말

### 함수

뜻: 입력값을 받아 어떤 작업을 수행하고 결과를 돌려주는 코드 단위입니다.

헷갈리기 쉬운 점: 함수는 작을수록 좋다는 말보다 한 가지 책임이 분명한가를 먼저 보는 편이 좋습니다.

### 클래스

뜻: 데이터와 동작을 묶어 설계도를 표현하는 문법 장치입니다.

헷갈리기 쉬운 점: 객체지향 언어에서 자주 등장하지만, 좋은 설계가 항상 클래스를 많이 만드는 것과 같지는 않습니다.

### 객체

뜻: 상태와 동작을 함께 가진 실행 단위 또는 개념적 대상을 코드로 옮긴 결과입니다.

헷갈리기 쉬운 점: 클래스는 설계도, 객체는 실제로 만들어진 인스턴스라고 보면 이해가 쉽습니다.

### 모듈

뜻: 관련 있는 코드 묶음을 파일이나 패키지 단위로 나눈 것입니다.

헷갈리기 쉬운 점: 모듈화의 핵심은 양을 줄이는 것이 아니라 변경 영향을 줄이는 것입니다.

### 컴포넌트

뜻: 화면이나 기능을 재사용 가능한 단위로 쪼갠 조각입니다.

헷갈리기 쉬운 점: 프론트엔드에서 자주 쓰이지만, 더 넓게는 독립적인 기능 단위라는 뜻으로도 쓰입니다.

### API

뜻: 프로그램끼리 기능과 데이터를 주고받는 약속입니다.

헷갈리기 쉬운 점: 메뉴판처럼 무엇을 요청할 수 있는지 정해 둔 것에 가깝지, 그 자체가 서버 전체를 뜻하는 것은 아닙니다.

### OpenAPI

뜻: REST API 같은 웹 API를 문서화하고 기계가 읽을 수 있게 표현하는 규격입니다.

헷갈리기 쉬운 점: API와 OpenAPI는 같은 말이 아닙니다. OpenAPI는 API를 설명하는 표준 형식에 가깝습니다.

### REST API

뜻: HTTP를 활용해 자원 중심으로 설계하는 방식입니다.

헷갈리기 쉬운 점: URL만 예쁘게 만든다고 REST가 되는 것은 아니며, 자원과 행위를 어떻게 나누는지가 중요합니다.

### JSON

뜻: 사람과 프로그램이 비교적 쉽게 읽을 수 있는 데이터 표현 형식입니다.

헷갈리기 쉬운 점: JSON은 프로그램이 아니라 데이터 형식입니다.

### XML

뜻: 태그 기반으로 구조를 표현하는 데이터 형식입니다.

헷갈리기 쉬운 점: 요즘 JSON이 더 자주 보이지만 XML이 사라진 것은 아닙니다. 문서형 구조와 오래된 시스템 통합에서는 여전히 등장합니다.

### 동기

뜻: 요청한 작업이 끝날 때까지 기다리며 순서대로 처리하는 방식입니다.

헷갈리기 쉬운 점: 느리다의 뜻이 아니라, 기다림이 흐름을 막는 구조인지에 더 가깝습니다.

### 비동기

뜻: 작업 완료를 기다리는 동안 다른 일을 진행할 수 있게 설계한 방식입니다.

헷갈리기 쉬운 점: 동시에 완전히 병렬로 돈다는 뜻과는 다를 수 있습니다.

### 이벤트

뜻: 특정 조건이 발생했음을 알리는 신호입니다.

헷갈리기 쉬운 점: 버튼 클릭만 이벤트가 아니라, 네트워크 응답 도착, 파일 변경, 타이머 만료도 모두 이벤트가 될 수 있습니다.

## 3. 데이터와 저장에서 자주 만나는 말

### DBMS

뜻: 데이터를 저장, 조회, 수정, 보호하는 일을 체계적으로 맡는 소프트웨어입니다.

헷갈리기 쉬운 점: 데이터베이스라는 말이 데이터를 담는 공간까지 포함해 넓게 쓰일 때가 있지만, DBMS는 그 공간을 관리하는 시스템에 더 가깝습니다.

### SQL

뜻: 관계형 데이터베이스와 대화할 때 자주 쓰는 질의 언어입니다.

헷갈리기 쉬운 점: SQL은 데이터베이스 제품 이름이 아니라 언어 이름입니다.

### NoSQL

뜻: 전통적인 관계형 모델만 사용하지 않는 다양한 데이터 저장 방식의 묶음입니다.

헷갈리기 쉬운 점: SQL을 전혀 안 쓴다는 뜻이 아니라, 관계형 중심이 아닌 모델을 포함하는 넓은 범주라고 보는 편이 정확합니다.

### 스키마

뜻: 데이터가 어떤 구조와 규칙을 따라 저장될지 정한 설계입니다.

헷갈리기 쉬운 점: 스키마가 엄격하다고 무조건 나쁜 것이 아니라, 데이터 품질과 변경 비용의 균형 문제입니다.

### 테이블

뜻: 관계형 데이터베이스에서 행과 열 형태로 데이터를 저장하는 기본 구조입니다.

헷갈리기 쉬운 점: 엑셀과 비슷해 보여도, 제약 조건과 관계 설계가 들어간다는 점에서 훨씬 엄격합니다.

### 쿼리

뜻: 데이터베이스에 요청을 보내는 문장 또는 명령입니다.

헷갈리기 쉬운 점: 조회만 쿼리가 아니라 삽입, 수정, 삭제 요청도 모두 넓게는 쿼리에 들어갑니다.

### 인덱스

뜻: 검색 속도를 높이기 위해 추가로 만든 데이터 구조입니다.

헷갈리기 쉬운 점: 인덱스가 많을수록 무조건 좋은 것은 아닙니다. 쓰기 비용과 저장 공간이 늘기 때문입니다.

### 트랜잭션

뜻: 여러 데이터 작업을 하나의 묶음으로 처리해 성공 또는 실패를 함께 보장하는 단위입니다.

헷갈리기 쉬운 점: 계좌 이체처럼 중간에 한쪽만 성공하면 안 되는 작업에서 특히 중요합니다.

### 정규화

뜻: 데이터 중복을 줄이고 구조를 안정적으로 만들기 위해 테이블을 분리하는 과정입니다.

헷갈리기 쉬운 점: 항상 많이 쪼개는 것이 좋은 것은 아니며, 조회 패턴과 성능도 함께 봐야 합니다.

### ORM

뜻: 코드의 객체 구조와 데이터베이스 테이블을 연결해 다루기 쉽게 해 주는 도구입니다.

헷갈리기 쉬운 점: SQL을 몰라도 된다는 뜻이 아니라, SQL을 더 높은 추상화로 감싸 주는 도구에 가깝습니다.

## 4. 운영체제와 실행 환경에서 자주 만나는 말

### 운영체제

뜻: 하드웨어 자원을 관리하고 프로그램 실행을 중재하는 기본 소프트웨어입니다.

헷갈리기 쉬운 점: 화면을 보여 주는 것만 운영체제가 아니라, 메모리 관리와 프로세스 관리가 핵심 역할입니다.

### 커널

뜻: 운영체제의 핵심 부분으로, 하드웨어와 소프트웨어 사이를 직접 조정합니다.

헷갈리기 쉬운 점: 운영체제 전체와 커널은 같은 말이 아닙니다. 커널은 중심부입니다.

### 프로그램

뜻: 파일 형태로 저장된 코드와 자원 묶음입니다.

헷갈리기 쉬운 점: 디스크에 가만히 있는 상태라면 아직 실행 중이 아닙니다.

### 프로세스

뜻: 실행 중인 프로그램 단위입니다.

헷갈리기 쉬운 점: 같은 프로그램을 두 번 실행하면 두 개의 프로세스가 생길 수 있습니다.

### 스레드

뜻: 프로세스 안에서 실제 작업이 흐르는 실행 단위입니다.

헷갈리기 쉬운 점: 프로세스보다 가볍지만 자원을 공유하기 때문에 동기화 문제가 생기기 쉽습니다.

### 메모리

뜻: 실행 중인 데이터와 코드를 잠시 올려 두는 작업 공간입니다.

헷갈리기 쉬운 점: 저장장치보다 빠르지만 용량이 제한되어 있습니다.

### 가상 메모리

뜻: 메모리가 부족할 때 저장장치를 일부 메모리처럼 활용하는 기법입니다.

헷갈리기 쉬운 점: 메모리가 갑자기 무한해지는 것이 아니라, 느려지는 대가를 치르며 공간을 넓히는 것입니다.

### 캐시 메모리

뜻: 자주 쓰는 데이터를 더 빠르게 접근하기 위해 가까운 곳에 임시로 저장한 공간입니다.

헷갈리기 쉬운 점: 브라우저 캐시와 CPU 캐시는 모두 같은 발상에서 출발하지만 위치와 목적이 다릅니다.

### 컨텍스트 스위칭

뜻: CPU가 한 작업에서 다른 작업으로 전환하는 과정입니다.

헷갈리기 쉬운 점: 동시 실행처럼 보여도 실제로는 빠른 전환의 결과인 경우가 많습니다.

### 파일 시스템

뜻: 데이터를 파일과 폴더 형태로 저장하고 관리하는 규칙입니다.

헷갈리기 쉬운 점: 운영체제마다 파일 권한과 경로 규칙이 달라서 개발 환경 차이의 원인이 되기도 합니다.

## 5. 네트워크와 서비스 운영에서 자주 만나는 말

### 클라이언트

뜻: 서비스를 요청하는 쪽입니다. 브라우저, 모바일 앱, 다른 서버도 클라이언트가 될 수 있습니다.

헷갈리기 쉬운 점: 사람이 직접 보는 화면만 클라이언트인 것은 아닙니다.

### 서버

뜻: 요청을 받아 처리하고 결과를 돌려주는 쪽입니다.

헷갈리기 쉬운 점: 한 대의 물리 컴퓨터만 서버가 아니라, 그 역할을 맡는 프로그램과 환경을 함께 가리키기도 합니다.

### 프로토콜

뜻: 통신할 때 지켜야 하는 규칙입니다.

헷갈리기 쉬운 점: HTTP, TCP, TLS 같은 말은 모두 통신 규칙의 층이 다릅니다.

### HTTP

뜻: 웹에서 가장 널리 쓰이는 요청-응답 통신 규칙입니다.

헷갈리기 쉬운 점: 인터넷 전체를 뜻하는 말이 아니라, 여러 프로토콜 중 웹에 가까운 하나입니다.

### HTTPS

뜻: HTTP 통신에 암호화 계층을 더해 더 안전하게 만든 방식입니다.

헷갈리기 쉬운 점: HTTPS가 붙는다고 사이트가 완벽히 안전해지는 것은 아니지만, 최소한의 기본선에 가깝습니다.

### 요청

뜻: 클라이언트가 서버에 보내는 일의 시작 신호입니다.

헷갈리기 쉬운 점: URL만 보내는 것이 아니라 메서드, 헤더, 본문 등을 함께 보낼 수 있습니다.

### 응답

뜻: 서버가 요청을 처리한 뒤 돌려주는 결과입니다.

헷갈리기 쉬운 점: 성공 데이터뿐 아니라 오류 코드와 메시지도 응답입니다.

### 쿠키

뜻: 브라우저에 저장되는 작은 데이터 조각입니다.

헷갈리기 쉬운 점: 무조건 로그인 정보라는 뜻은 아니며, 설정값과 추적 정보에도 쓰입니다.

### 세션

뜻: 서버가 사용자 상태를 일정 기간 기억하기 위한 개념입니다.

헷갈리기 쉬운 점: 쿠키와 세션은 경쟁 개념이 아니라 함께 쓰일 때가 많습니다.

### JWT

뜻: 사용자 정보와 검증 정보를 토큰 안에 담아 전달하는 방식입니다.

헷갈리기 쉬운 점: 토큰 안에 정보가 들어 있다고 해서 언제나 안전한 것은 아니며, 만료와 저장 위치가 중요합니다.

### 로드밸런서

뜻: 여러 서버로 요청을 분산해 과부하를 줄이는 장치 또는 서비스입니다.

헷갈리기 쉬운 점: 무조건 큰 서비스에서만 쓰는 것이 아니라, 가용성과 확장성을 고민할 때 자연스럽게 등장합니다.

### 캐시

뜻: 다시 계산하거나 다시 가져오지 않도록 결과를 임시 저장하는 전략입니다.

헷갈리기 쉬운 점: 빠르기만 하면 좋은 것이 아니라, 오래된 데이터가 남는 문제도 함께 관리해야 합니다.

## 6. 아키텍처, 클라우드, AI에서 자주 만나는 말

### 아키텍처

뜻: 시스템을 어떤 경계와 책임으로 나누고 연결할지 정한 큰 구조입니다.

헷갈리기 쉬운 점: 예쁜 다이어그램이 아니라, 변경 비용과 장애 확산을 통제하는 방식에 가깝습니다.

### 모놀리식

뜻: 여러 기능이 하나의 큰 애플리케이션으로 묶여 동작하는 구조입니다.

헷갈리기 쉬운 점: 무조건 낡은 구조가 아니라, 초기에는 오히려 단순해서 강점이 될 수 있습니다.

### MSA

뜻: 기능을 여러 독립 서비스로 나누어 개발하고 운영하는 구조입니다.

헷갈리기 쉬운 점: 작게 나눈다고 자동으로 좋아지지 않으며, 네트워크·배포·관측 복잡성이 함께 늘어납니다.

### 클라우드

뜻: 인터넷을 통해 서버, 저장소, 데이터베이스 같은 자원을 빌려 쓰는 방식입니다.

헷갈리기 쉬운 점: 그냥 남의 컴퓨터라는 말은 절반만 맞습니다. 핵심은 자원 관리와 운영 방식까지 서비스화되었다는 점입니다.

### IaaS

뜻: 기본 인프라 자원을 빌려 쓰는 서비스 모델입니다.

헷갈리기 쉬운 점: 제어권은 크지만 직접 관리해야 할 일도 많습니다.

### PaaS

뜻: 애플리케이션 실행 환경까지 관리해 주는 서비스 모델입니다.

헷갈리기 쉬운 점: 개발 속도는 빠르지만 플랫폼 제약이 생길 수 있습니다.

### SaaS

뜻: 완성된 소프트웨어를 서비스 형태로 사용하는 모델입니다.

헷갈리기 쉬운 점: 사용자는 기능을 곧바로 쓰지만 내부 구현 제어권은 거의 없습니다.

### 서버리스

뜻: 서버를 아예 안 쓰는 것이 아니라, 서버 운영 관리 부담을 크게 줄인 실행 방식입니다.

헷갈리기 쉬운 점: 짧은 작업과 이벤트 기반 처리에는 강하지만 모든 상황의 만능 해답은 아닙니다.

### 컨테이너

뜻: 애플리케이션과 실행 환경을 함께 묶어 어디서든 비슷하게 실행되게 만드는 방식입니다.

헷갈리기 쉬운 점: 가상머신과 비슷해 보여도 공유하는 층과 무게가 다릅니다.

### 쿠버네티스

뜻: 많은 컨테이너를 배치하고 확장하고 복구하는 일을 자동화하는 플랫폼입니다.

헷갈리기 쉬운 점: 도커와 같은 말이 아니며, 훨씬 큰 운영 계층입니다.

### 머신러닝

뜻: 데이터에서 패턴을 학습해 예측이나 분류를 수행하는 기술입니다.

헷갈리기 쉬운 점: 인공지능 전체와 같은 말이 아니라, AI 안의 한 갈래로 보는 편이 정확합니다.

### 인공지능

뜻: 사람의 지능적 작업처럼 보이는 기능을 구현하려는 넓은 분야입니다.

헷갈리기 쉬운 점: 무엇이든 자동으로 해결하는 마법이 아니라, 문제 정의와 데이터 품질, 운영 방식의 영향을 크게 받습니다.

### 프롬프트

뜻: AI 모델에게 원하는 작업과 맥락을 전달하는 입력입니다.

헷갈리기 쉬운 점: 질문을 길게 쓴다고 항상 좋아지는 것은 아니고, 맥락과 제약을 분명히 주는 편이 더 중요합니다.

## 용어집을 보는 요령

용어를 볼 때 가장 좋은 질문은 "이 말은 어느 층의 이야기인가"입니다. 사람의 역할을 말하는지, 코드 구조를 말하는지, 데이터 저장을 말하는지, 네트워크 규칙을 말하는지 먼저 분류해 보세요. 이 한 단계만으로도 비슷한 말이 한꺼번에 섞이는 문제가 크게 줄어듭니다.

또 하나 중요한 점은, 정의를 외운다고 이해가 끝나지 않는다는 사실입니다. API, 세션, 트랜잭션, 컨테이너 같은 말은 실제 장면과 붙을 때 비로소 기억에 남습니다. 그러니 용어집에서 뜻을 확인한 뒤에는 반드시 본문에서 예시가 나온 절로 다시 돌아가 보세요. 그 왕복이 쌓일수록 지식이 훨씬 단단해집니다.
