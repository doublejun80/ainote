# 부록. 미니 프로젝트 설계 노트

책을 읽고 나면 많은 사람이 같은 고민을 합니다. "그래서 뭘 만들어 봐야 하지?" 이 질문은 아주 중요합니다. 개념은 손을 움직여 볼 때 비로소 오래 남기 때문입니다. 하지만 처음부터 거대한 프로젝트를 잡으면 개념을 확인하기도 전에 지쳐 버리기 쉽습니다. 그래서 이 부록에서는 작지만 연결이 잘 되는 프로젝트를 제안합니다.

좋은 미니 프로젝트는 세 가지 조건을 만족해야 합니다. 첫째, 하나의 핵심 흐름이 분명해야 합니다. 둘째, 책의 여러 장을 자연스럽게 다시 열어 보게 만들어야 합니다. 셋째, 실패해도 금방 줄여서 다시 시도할 수 있어야 합니다. 아래 프로젝트들은 이 기준에 맞추어 골랐습니다.

## 프로젝트 1. 개인 메모 앱

### 이 프로젝트가 좋은 이유

가장 작게 시작할 수 있으면서도, 화면 입력, 목록 표시, 저장, 수정, 삭제라는 기본 흐름을 모두 담고 있습니다. 즉, 2장의 웹 애플리케이션 개념, 3장의 프론트엔드 도구 선택, 4장의 API와 비동기, 7장의 데이터 저장 기초를 한 번에 다시 꺼내 보게 됩니다.

### 최소 기능 범위

- 메모 작성
- 메모 목록 보기
- 메모 수정
- 메모 삭제
- 간단한 검색 또는 정렬 중 하나

처음부터 사용자 로그인까지 붙이려 하지 않는 편이 좋습니다. 메모의 생성, 조회, 수정, 삭제 흐름이 먼저 안정되어야 합니다.

### 자주 막히는 지점

초보자는 화면은 빠르게 만들지만 저장 구조를 뒤로 미루는 경우가 많습니다. 반대로 백엔드부터 잡겠다고 하다가 화면 연결에서 멈추는 경우도 많습니다. 이 프로젝트에서는 두 극단을 피하고, "입력-저장-다시 보여 주기"의 최소 흐름을 먼저 완성하는 것이 핵심입니다.

### 확장 아이디어

태그 달기, 즐겨찾기, 작성일 정렬, 간단한 로그인 기능, 모바일 화면 대응까지 차근차근 붙일 수 있습니다. 확장은 언제나 현재 흐름이 흔들리지 않는다는 전제 위에서만 하는 편이 좋습니다.

## 프로젝트 2. 로그인 기능이 있는 작은 서비스

### 이 프로젝트가 좋은 이유

쿠키, 세션, JWT, 사용자 테이블, 비밀번호 저장, 인증 흐름이 한꺼번에 등장하기 때문에 7장과 8장을 실제 장면으로 바꾸기에 좋습니다. 초보자는 인증을 "어려운 보안 기능"으로만 생각하기 쉬운데, 작은 서비스로 직접 만들어 보면 훨씬 현실적으로 이해하게 됩니다.

### 최소 기능 범위

- 회원가입
- 로그인
- 로그아웃
- 로그인한 사용자만 볼 수 있는 페이지 하나
- 잘못된 로그인 시 오류 메시지 보여 주기

### 자주 막히는 지점

가장 흔한 문제는 상태 유지가 어디에서 일어나는지 감을 놓치는 것입니다. 브라우저에 무엇이 남는지, 서버는 무엇을 기억하는지, 토큰은 어디에 저장할지, 만료는 어떻게 처리할지를 차례대로 나눠 보아야 합니다. 인증은 한 번에 다 이해하려 하기보다 흐름을 자주 다시 그려 보는 편이 좋습니다.

### 확장 아이디어

비밀번호 재설정, 이메일 인증, 역할 분리, 관리자 페이지 등으로 확장할 수 있습니다. 다만 이 단계에서는 기능을 늘리기보다 인증 실패와 예외 흐름을 차분히 다루는 연습이 더 중요합니다.

## 프로젝트 3. 예약 또는 주문 흐름

### 이 프로젝트가 좋은 이유

여러 단계가 연결된 흐름을 다루기 때문에 자료 구조, 트랜잭션, 상태 관리, 오류 처리의 중요성이 한꺼번에 드러납니다. 상품 담기, 시간대 예약, 결제 흉내 내기 같은 흐름은 현실적인 서비스 감각을 빠르게 만들어 줍니다.

### 최소 기능 범위

- 예약 가능한 자원 또는 상품 목록 보기
- 한 항목 선택하기
- 확정 요청 보내기
- 성공 또는 실패 결과 보여 주기
- 중복 예약 또는 재고 부족 같은 예외 하나 처리하기

### 자주 막히는 지점

초보자는 성공 흐름만 그리고 실패 흐름을 빼먹는 경우가 많습니다. 하지만 실제 서비스는 실패 처리에서 더 많은 구조적 판단이 필요합니다. 예를 들어 두 사람이 같은 시간대를 동시에 예약하려 할 때 무엇을 기준으로 막을지, 어디에서 검증할지, 실패 메시지는 어디서 만들지를 나눠 보아야 합니다.

### 확장 아이디어

결제 연동 흉내 내기, 관리자 승인 흐름, 예약 취소, 알림 보내기 같은 기능으로 확장할 수 있습니다. 이때는 9장의 아키텍처 감각도 함께 살아납니다.

## 프로젝트 4. 파일 업로드와 미리보기 기능

### 이 프로젝트가 좋은 이유

프론트엔드와 백엔드의 역할, 저장소 선택, 네트워크 요청, 예외 처리, 보안 기초를 함께 확인할 수 있기 때문입니다. 단순해 보여도 파일 크기 제한, 형식 검증, 업로드 상태 표시, 저장 위치 관리 등 생각보다 많은 주제가 붙습니다.

### 최소 기능 범위

- 파일 선택
- 업로드 진행 상태 보여 주기
- 업로드 완료 후 미리보기 또는 링크 보여 주기
- 잘못된 형식이나 큰 파일에 대한 오류 처리

### 자주 막히는 지점

파일을 "그냥 전송하는 데이터"로만 생각하면 금방 막힙니다. 실제로는 브라우저에서 어떤 형식으로 보내는지, 서버는 어디에 저장하는지, DB에는 무엇을 남기는지, 공개 URL은 어떻게 관리할지까지 생각해야 합니다. 이 프로젝트는 8장의 요청-응답과 10장의 클라우드 저장 개념을 연결하기에 좋습니다.

## 프로젝트 5. 간단한 대시보드 또는 통계 화면

### 이 프로젝트가 좋은 이유

데이터를 단순 저장하는 것에서 한 걸음 더 나아가, 읽기 좋게 가공하고 보여 주는 훈련이 되기 때문입니다. 차트 라이브러리를 붙이는 것이 핵심이 아니라, 무엇을 집계하고 어떻게 보여 주어야 의미가 생기는지 고민하는 과정이 중요합니다.

### 최소 기능 범위

- 목록 데이터 가져오기
- 집계 수치 두세 개 계산하기
- 날짜 또는 상태 기준으로 필터 하나 만들기
- 그래프 또는 카드 형태로 결과 보여 주기

### 자주 막히는 지점

조회 성능과 데이터 가공 위치를 어디에 둘지 헷갈리기 쉽습니다. 서버에서 가공할지, 클라이언트에서 가공할지, 캐시를 둘지, 실시간처럼 보이게 할지 같은 질문이 생깁니다. 이런 고민이 바로 네트워크, 데이터베이스, 아키텍처를 다시 읽게 만드는 계기가 됩니다.

## 프로젝트 6. AI 보조 기능이 붙은 작은 도구

### 이 프로젝트가 좋은 이유

AI를 붙이는 순간 오히려 기본 구조의 중요성이 더 잘 드러납니다. 요청을 어떻게 보내는지, 결과를 어디까지 믿을지, 실패했을 때 어떻게 처리할지, 비용과 속도를 어떻게 볼지 같은 질문이 자연스럽게 생기기 때문입니다.

### 최소 기능 범위

- 사용자 입력 받기
- AI 요약 또는 분류 결과 보여 주기
- 결과를 저장하거나 복사하기
- 오류나 지연 상태를 화면에서 알리기
- 사람이 다시 확인해야 하는 이유를 한 줄로 안내하기

### 자주 막히는 지점

많은 초보자가 AI 결과를 바로 정답처럼 다루려 합니다. 하지만 실제 도구는 AI 호출 자체보다, 결과를 어떻게 검증하고 사용자에게 어떻게 보여 줄지를 더 많이 고민합니다. 즉, 이 프로젝트는 10장의 AI 이야기와 4장의 API, 8장의 네트워크, 7장의 데이터 저장을 한 번에 묶어 주는 좋은 연습입니다.

## 프로젝트를 작게 유지하는 기준

미니 프로젝트는 작게 시작할수록 좋습니다. 기능은 적어도 괜찮지만, 흐름은 끝까지 이어져야 합니다. 아래 기준을 기억해 두면 프로젝트가 불필요하게 커지는 것을 막을 수 있습니다.

- 화면은 한두 개만 둔다.
- 데이터 종류는 세 개를 넘기지 않는다.
- 인증은 정말 필요한 경우에만 붙인다.
- 예외 흐름은 한두 개만 확실히 처리한다.
- 배포까지 가기 어렵다면 로컬 실행이라도 끝까지 연결한다.

이 기준은 야심을 꺾기 위한 것이 아닙니다. 실제로는 작게 끝까지 가는 경험이, 크게 시작하고 포기하는 경험보다 훨씬 많은 것을 가르쳐 줍니다.

## 프로젝트 회고를 남기는 방법

프로젝트가 끝났을 때 무엇을 만들었는지만 적지 말고, 무엇을 몰랐고 어디서 막혔는지도 기록하세요. 특히 아래 질문에 답해 보면 다음 프로젝트의 속도가 빨라집니다.

- 내가 가장 오래 붙잡힌 부분은 무엇이었는가
- 그 문제는 용어 부족 때문이었는가, 흐름 부족 때문이었는가, 구현 경험 부족 때문이었는가
- 책의 어느 장을 다시 보니 해결이 빨라졌는가
- 다음에는 무엇을 더 작게 시작해야 하는가

개발은 정답을 많이 맞히는 훈련이 아니라, 막히는 지점을 더 빨리 분류하고 복구하는 훈련에 가깝습니다. 그래서 미니 프로젝트 설계 노트는 단순한 과제 목록이 아니라, 책을 실제 손의 감각으로 옮기기 위한 다리 역할을 합니다.
