# HTTP는 무엇인가요?

HTTP는 웹에서 클라이언트와 서버가 요청과 응답을 주고받는 방법을 정한 프로토콜입니다. 브라우저가 페이지를 달라고 하거나, 앱이 서버에 데이터를 보낼 때 가장 자주 보게 되는 규칙입니다. 초보자는 HTTP를 인터넷 전체와 같은 뜻으로 받아들이기도 하지만, 더 정확히는 웹 통신의 문법이라고 보는 편이 맞습니다.

HTTP 요청에는 보통 무엇을 원하는지, 어떤 방식으로 원하는지, 추가 정보가 무엇인지가 담깁니다. 예를 들어 `GET`은 조회, `POST`는 새 데이터 전송이나 생성에 자주 쓰입니다. 응답에는 결과 본문뿐 아니라 상태 코드와 헤더가 포함됩니다. 상태 코드는 200, 404, 500처럼 결과 상태를 숫자로 알려 주고, 헤더는 캐시, 인증, 데이터 형식 같은 부가 정보를 전달합니다.

## HTTP를 이해하면 왜 좋은가요

많은 웹 개발 문제는 결국 HTTP 레벨에서 드러납니다. 요청 메서드가 맞는지, 응답 상태 코드가 무엇인지, 헤더가 올바른지, 본문 형식이 JSON인지 파일인지에 따라 동작이 달라집니다. 네트워크 탭에서 보이는 정보 대부분이 HTTP 수준의 정보이기 때문에, 이 개념을 이해하면 디버깅이 훨씬 쉬워집니다.

또한 HTTP는 원래 무상태에 가깝게 설계되어 있어, 요청 하나하나가 독립적으로 처리되기 쉽습니다. 이 때문에 로그인 상태 유지나 사용자별 맞춤 동작을 하려면 쿠키, 세션, 토큰 같은 추가 장치가 등장합니다. 즉, HTTP를 이해하면 왜 인증 기술이 따로 필요한지도 함께 보이게 됩니다.

## 요청과 응답을 어떻게 읽어야 하나요

초보자는 본문 데이터만 보고 싶어 하지만, 실무에서는 상태 코드와 헤더가 매우 중요합니다. 200은 성공, 301과 302는 이동, 401은 인증 필요, 403은 금지, 404는 없음, 500은 서버 내부 오류처럼 읽을 수 있습니다. 헤더에는 콘텐츠 타입, 캐시 정책, 인증 정보, 쿠키 등 중요한 정보가 담깁니다.

즉, HTTP는 단지 데이터를 실어 나르는 통로가 아니라, 요청의 의도와 응답의 의미를 풍부하게 표현하는 구조입니다. 이 구조를 읽을 수 있으면 브라우저 개발자 도구와 API 문서가 훨씬 덜 낯설어집니다.

## 초보자가 꼭 기억해야 할 한 가지

HTTP는 웹에서 대화를 하는 규칙이라는 점입니다. 누가 무엇을 원하고, 어떤 형식으로 주고받고, 결과가 성공인지 실패인지 합의하는 규칙입니다. 그 합의가 있기 때문에 브라우저와 서버와 API 도구들이 서로 통할 수 있습니다.

이 감각만 분명해도 HTTP는 더 이상 어려운 약자가 아니라, 웹 개발의 기본 문장 구조로 보이기 시작합니다.

## HTTP 메시지를 볼 때 먼저 읽는 것

HTTP 메시지를 볼 때는 먼저 세 가지를 읽으면 됩니다. 무엇을 요청했는지(URL과 메서드), 결과가 어땠는지(상태 코드), 어떤 데이터가 오갔는지(헤더와 본문)입니다. 이 세 축만 잡아도 브라우저 개발자 도구의 네트워크 탭이 훨씬 덜 무섭습니다. 초보자는 모든 헤더를 외우려 하지 말고, 요청과 응답의 큰 의미를 읽는 데부터 익숙해지면 됩니다.

정리하면, HTTP는 웹에서 요청과 응답의 형식과 의미를 정하는 프로토콜입니다. 메서드, 상태 코드, 헤더, 본문이 함께 동작하며 웹 서비스의 기본 대화를 이룹니다. 개발자는 HTTP를 이해할수록 API 문서와 네트워크 오류를 훨씬 더 정확하게 읽을 수 있습니다.
