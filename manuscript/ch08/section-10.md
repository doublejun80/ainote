# JWT란 무엇인가요?

JWT는 JSON Web Token의 약자로, 사용자 정보나 권한 같은 클레임을 담아 서명된 형태로 전달하는 토큰 방식입니다. 초보자는 JWT를 로그인 그 자체로 오해하기 쉽지만, 더 정확히 말하면 인증과 권한 확인에 활용될 수 있는 전달 형식입니다. 즉, 사용자를 증명하는 정보 조각을 네트워크에서 다루기 쉽게 만든 포맷입니다.

JWT는 보통 점으로 나뉜 세 부분으로 이루어집니다. 헤더, 페이로드, 서명입니다. 페이로드에는 사용자 아이디, 만료 시간, 역할 같은 정보가 들어갈 수 있고, 서명은 이 내용이 임의로 바뀌지 않았는지 검증하는 데 사용됩니다. 여기서 중요한 점은 서명은 위조 방지에 가깝지, 내용 자체를 숨기는 암호화와는 다를 수 있다는 것입니다.

## 왜 JWT가 널리 쓰였나요

서버가 모든 로그인 상태를 별도 세션 저장소에 보관하지 않아도, 토큰 안에 필요한 정보를 담아 비교적 간편하게 검증할 수 있기 때문입니다. 특히 여러 서버가 분산된 환경이나 모바일 앱, 외부 API 연동 환경에서는 토큰 기반 인증이 편리할 때가 많습니다. 클라이언트는 로그인 후 받은 토큰을 보관했다가 이후 요청에 함께 보냅니다.

서버는 토큰 서명을 확인하고, 만료 여부를 보고, 필요한 권한 정보를 읽어 요청을 처리할 수 있습니다. 이렇게 하면 세션 저장소 의존성을 줄일 수 있지만, 대신 토큰 발급과 갱신, 만료 전략을 잘 설계해야 합니다.

## JWT를 쓸 때 자주 생기는 오해

첫째, JWT는 암호화된 비밀 상자가 아닙니다. 기본적으로는 인코딩과 서명이 중심이므로, 민감한 정보를 무턱대고 넣으면 안 됩니다. 둘째, JWT를 쓴다고 해서 자동으로 더 안전해지는 것도 아닙니다. 탈취되면 위험할 수 있으므로 저장 위치, 만료 시간, 재발급 방식, HTTPS 사용 여부가 중요합니다.

셋째, JWT가 모든 로그인 구조의 정답도 아닙니다. 관리가 간단한 세션 기반 구조가 더 적절한 경우도 많습니다. 즉, JWT는 유행어가 아니라 상황에 맞는 선택지입니다.

## 초보자는 어떻게 이해하면 좋을까요

JWT는 사용자에 대한 몇 가지 정보를 담은 신분증 비슷한 토큰이라고 생각하면 됩니다. 서버는 그 신분증이 위조되지 않았는지 확인하고, 유효 기간과 권한 정보를 보고 요청을 처리합니다. 다만 신분증을 들고 다니는 방식인 만큼 잃어버렸을 때의 위험과 갱신 규칙도 함께 생각해야 합니다.

이 감각을 잡으면 인증 구조를 볼 때 세션 기반인지 토큰 기반인지, 그리고 왜 그런 선택을 했는지 조금 더 분명하게 읽을 수 있습니다.

## JWT를 편하게 쓰려다 놓치기 쉬운 점

JWT는 편리하지만, 편리한 만큼 어디에 저장하고 언제 폐기할지 더 신중해야 합니다. 토큰 안에 정보가 담겨 있어 서버가 매번 세션 저장소를 보지 않아도 된다는 장점이 있지만, 탈취되었을 때 처리 전략과 갱신 정책을 함께 설계하지 않으면 위험해질 수 있습니다. 그래서 JWT는 만능 인증이 아니라, stateless한 장점과 보안 운영 부담을 함께 가져오는 선택입니다. 구현보다 운영 규칙이 더 중요할 때가 많습니다.

정리하면, JWT는 사용자 정보와 권한 정보를 담아 서명된 형태로 전달하는 토큰 포맷입니다. 서버는 이를 검증해 인증과 권한 확인에 활용할 수 있습니다. 편리하지만 만능은 아니며, 저장 방식과 만료 전략과 보안 설계가 함께 따라와야 합니다.
