# 라우터, 스위치, 로드밸런서는 무엇인가요?

이 세 용어는 모두 네트워크에서 길을 정하거나 트래픽을 분산하는 역할과 관련이 있지만, 맡는 일이 다릅니다. 라우터는 서로 다른 네트워크 사이에서 길을 찾아 주는 장치입니다. 스위치는 같은 네트워크 안에서 어느 장치로 데이터를 보낼지 연결해 주는 장치입니다. 로드밸런서는 여러 서버 중 어느 서버가 요청을 처리할지 분산해 주는 장치 또는 기능입니다.

쉽게 말하면 스위치는 같은 건물 안에서 어느 방으로 보낼지 정하는 역할, 라우터는 다른 건물로 가는 길을 찾는 역할, 로드밸런서는 손님을 여러 직원에게 적절히 나눠 주는 역할이라고 생각할 수 있습니다. 이름이 비슷해 보여도 문제를 해결하는 층이 다릅니다.

## 개발자가 왜 이 장비 이름을 알아야 하나요

클라우드나 서버 운영을 하다 보면 서비스가 어디에서 막히는지 이해해야 할 순간이 옵니다. 같은 네트워크 안의 장치 문제인지, 외부 네트워크로 나가는 길 문제인지, 서버 한 대에 요청이 몰리는 문제인지에 따라 대응이 달라집니다. 이때 라우터, 스위치, 로드밸런서의 역할을 구분할 수 있어야 인프라 대화를 따라갈 수 있습니다.

특히 로드밸런서는 개발자에게 매우 가깝습니다. 서버가 여러 대일 때 요청을 고르게 나누고, 특정 서버가 죽으면 다른 서버로 보내고, 헬스 체크를 통해 장애 대응을 돕는 구조가 자주 등장하기 때문입니다. 대규모 서비스에서 확장성과 가용성을 이야기할 때 거의 빠지지 않는 개념입니다.

## 스위치와 라우터는 왜 따로 있나요

같은 네트워크 내부에서 장치끼리 연결하는 일과, 서로 다른 네트워크를 이어 주는 일은 성격이 다르기 때문입니다. 스위치는 주로 가까운 내부 연결을 효율적으로 다루고, 라우터는 더 넓은 범위에서 어느 길로 보내야 할지 판단합니다. 인터넷 자체도 수많은 라우팅 결정의 집합입니다.

초보자는 이 둘을 물리 장비 이름으로만 기억하기보다, 내부 연결과 외부 경로의 차이라고 이해하는 편이 훨씬 오래 갑니다.

## 초보자가 가져갈 핵심 감각

서비스가 커질수록 요청은 단순히 한 서버로 직행하지 않습니다. 네트워크 내부 연결, 외부 경로 결정, 여러 서버로의 분산이 함께 작동합니다. 라우터, 스위치, 로드밸런서는 그 흐름의 서로 다른 지점을 담당합니다.

이 감각을 알면 인프라 구조도를 볼 때 이름만 읽는 것이 아니라, 요청이 실제로 어떤 관문을 지나가는지 상상할 수 있게 됩니다.

## 세 장비는 어디서 차이를 만드나요

라우터, 스위치, 로드밸런서는 모두 길을 나눈다는 느낌이 있지만 보는 대상이 다릅니다. 라우터는 네트워크와 네트워크 사이의 길을 정하고, 스위치는 같은 네트워크 안에서 장비끼리 효율적으로 연결하며, 로드밸런서는 여러 서버로 요청을 나눠 보냅니다. 그래서 셋을 한꺼번에 장비 이름으로만 외우면 계속 헷갈립니다. 어디에서 무엇을 나누는지로 기억하는 편이 훨씬 쉽습니다.

정리하면, 스위치는 같은 네트워크 안에서 연결을 조정하고, 라우터는 서로 다른 네트워크 사이의 경로를 찾고, 로드밸런서는 여러 서버에 요청을 분산합니다. 세 용어는 모두 트래픽 흐름과 관련 있지만 맡는 층과 목적이 다릅니다. 초보자는 장비 이름보다 어떤 종류의 길목 문제를 해결하는지 중심으로 이해하는 것이 좋습니다.
