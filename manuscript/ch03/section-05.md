# 객체지향이란 무엇인가요?

객체지향이라는 말을 처음 들으면 대개 어렵게 느껴집니다. 클래스, 객체, 상속, 캡슐화, 다형성 같은 낯선 단어가 한꺼번에 나오기 때문입니다. 하지만 핵심 아이디어는 생각보다 단순합니다. 프로그램을 기능 덩어리와 데이터 묶음으로 나누어, 서로 역할을 가진 단위로 조직하려는 방식이라고 보면 됩니다.

쉽게 말해, 프로그램을 하나의 긴 절차로만 쓰지 않고 "이 일은 이 객체가 맡는다"라고 역할을 나누는 사고방식입니다. 현실 세계를 그대로 복사하는 것은 아니지만, 적어도 역할과 책임을 묶어 생각하게 도와줍니다.

## 왜 이런 방식이 필요했나

프로그램이 작을 때는 순서대로 쭉 써 내려가는 방식도 어느 정도 괜찮습니다. 하지만 규모가 커지면 어디서 어떤 데이터가 바뀌는지 추적하기 어려워지고, 기능을 추가할 때마다 기존 코드가 쉽게 엉키게 됩니다. 객체지향은 이런 복잡함을 줄이기 위해 등장한 여러 방법 중 하나입니다.

예를 들어 쇼핑몰 프로그램을 만든다고 할 때, 주문, 회원, 상품, 결제 같은 개념을 역할 단위로 나누어 다루면 구조를 파악하기 쉬워집니다. 주문과 관련된 데이터와 동작을 한곳에 모아 두면, 나중에 기능을 고칠 때도 찾기가 수월합니다.

## 객체지향에서 자주 나오는 말들

클래스는 설계도에 가깝고, 객체는 그 설계도로 만든 실제 대상에 가깝다고 이해하면 됩니다. 예를 들어 회원이라는 개념을 프로그램에 넣고 싶다면, 회원이 가져야 할 정보와 행동을 클래스에 적어 둘 수 있습니다. 그리고 실제 사용자 한 명 한 명은 객체로 만들어집니다.

캡슐화는 관련된 데이터와 기능을 하나로 묶고, 바깥에서 아무렇게나 건드리지 못하게 경계를 세우는 생각입니다. 상속은 기존 구조를 바탕으로 새로운 구조를 만드는 방식이고, 다형성은 같은 요청이라도 객체에 따라 다른 방식으로 반응하게 만드는 성질이라고 이해하면 됩니다. 초보자에게는 단어를 완벽히 외우기보다, "역할을 나누고 경계를 세우는 방법"이라는 큰 틀을 먼저 잡는 편이 더 중요합니다.

## 객체지향은 만능인가

여기서 꼭 짚고 넘어가야 할 점이 있습니다. 객체지향은 중요한 사고방식이지만, 모든 문제의 유일한 정답은 아닙니다. 어떤 프로그램은 절차적으로 쓰는 편이 더 단순하고, 어떤 문제는 함수형 스타일이나 데이터 중심 접근이 더 잘 맞기도 합니다.

즉, 객체지향을 배운다는 것은 세상을 객체로만 보라는 뜻이 아니라, 큰 프로그램을 조직하는 대표적인 방법 하나를 배우는 것입니다. 초보자는 특히 객체지향을 신비한 주문처럼 볼 필요가 없습니다. 코드가 커졌을 때 구조를 잡는 한 방법이라고 보면 충분합니다.

## 객체지향을 잘못 이해하면 생기는 일

객체지향을 잘못 배우면 모든 것을 클래스 안에만 넣으려 하거나, 현실의 사물을 억지로 코드와 일대일로 맞추려는 문제가 생깁니다. 중요한 것은 명사 찾기보다 책임을 어디에 둘지 정하는 일입니다. 누가 데이터를 갖고, 누가 상태를 바꾸고, 누가 규칙을 검사하는지 분리할 수 있어야 객체지향이 도움이 됩니다. 결국 객체지향은 모양보다 역할 배치에 더 가깝습니다.

정리하면, 객체지향은 프로그램을 역할과 책임이 있는 단위로 나누어 조직하려는 방식입니다. 클래스와 객체, 캡슐화와 상속 같은 개념은 그 구조화를 돕는 도구입니다. 중요한 것은 용어를 외우는 것보다, 왜 큰 프로그램에서 역할 분리가 필요한지 이해하는 것입니다.
