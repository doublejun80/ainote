# 모바일 앱을 개발하는 언어 및 프레임워크는 무엇인가요?

모바일 앱 개발은 크게 두 방향으로 생각할 수 있습니다. 하나는 안드로이드와 아이폰 각각에 맞는 방식으로 만드는 것이고, 다른 하나는 하나의 코드베이스를 최대한 여러 플랫폼에 함께 활용하는 방식입니다. 어떤 쪽을 고르느냐에 따라 언어와 프레임워크 선택도 달라집니다.

안드로이드 쪽에서는 Kotlin과 Java가 자주 언급되고, 아이폰 쪽에서는 Swift가 중심입니다. 이런 방식은 보통 네이티브 앱 개발이라고 부릅니다. 네이티브라는 말은 해당 운영체제의 공식 도구와 구조에 맞춰 개발한다는 뜻입니다. 기기 기능 접근, 성능, 운영체제와의 자연스러운 통합에서 강점이 큽니다.

## 여러 플랫폼을 함께 노리는 방식도 있다

요즘은 React Native와 Flutter 같은 크로스플랫폼 프레임워크도 많이 사용됩니다. 크로스플랫폼은 여러 운영체제에 하나의 코드베이스를 최대한 공유해 대응하려는 접근입니다. React Native는 자바스크립트와 리액트 경험을 활용하기 좋고, Flutter는 Dart 언어와 자체 UI 렌더링 방식으로 일관된 화면 제어에 강점을 보입니다.

초보자에게 중요한 것은 이 도구들이 서로 경쟁하는 이름표가 아니라는 점입니다. 네이티브와 크로스플랫폼은 서로 다른 장단점을 가진 전략입니다. 특정 제품에서는 네이티브가 더 맞고, 다른 제품에서는 크로스플랫폼이 더 현실적일 수 있습니다.

## 무엇을 기준으로 고르면 좋을까

기기 기능을 깊게 쓰고, 성능과 운영체제 경험이 매우 중요하다면 네이티브가 유리할 수 있습니다. 예를 들어 카메라, 블루투스, 센서, 복잡한 애니메이션이 핵심이라면 운영체제에 밀착된 방식이 강합니다.

반대로 팀 규모가 작고, 안드로이드와 iOS를 동시에 빠르게 내야 하며, 기능 실험 속도가 중요하다면 크로스플랫폼이 매력적일 수 있습니다. 특히 웹 프론트엔드 경험이 있는 팀은 React Native에 비교적 쉽게 적응하기도 합니다.

## 초보자는 어떻게 시작하는 것이 좋은가

처음부터 모든 플랫폼을 한꺼번에 비교하려 하면 부담이 큽니다. 모바일 개발이 궁금하다면 먼저 안드로이드나 iOS 중 하나를 이해해 보거나, 이미 웹 경험이 있다면 React Native 같은 진입점으로 시작해도 됩니다. 중요한 것은 앱이라는 결과물 뒤에 화면, 상태, 기기 기능, 배포, 스토어 등록 같은 여러 층이 있다는 사실을 함께 이해하는 것입니다.

## 모바일 선택지가 많은 이유

모바일 개발 선택지가 많은 이유는 목표 플랫폼과 팀 상황이 다르기 때문입니다. iOS와 Android를 각각 깊게 최적화하고 싶다면 네이티브가 유리할 수 있고, 빠르게 둘 다 내야 한다면 크로스플랫폼이 매력적일 수 있습니다. 또 앱이 기기 센서와 얼마나 가깝게 붙는지, 성능 요구가 높은지, 팀이 어떤 언어를 이미 알고 있는지도 큰 변수입니다. 그래서 모바일 개발은 정답 찾기보다 제약 조건 읽기에 가깝습니다.

정리하면, 모바일 앱 개발에는 네이티브 방식과 크로스플랫폼 방식이 있습니다. 안드로이드·iOS 공식 도구로 만드는 방법과, 하나의 코드베이스를 여러 플랫폼에 활용하는 방법 사이에서 선택하게 됩니다. 어떤 도구가 최고인지보다, 제품 요구와 팀 상황에 무엇이 맞는지가 더 중요합니다.
