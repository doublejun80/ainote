# XML, Json은 프로그램인가요? 어떻게 생긴건가요?

XML과 JSON은 프로그램이 아니라 데이터를 표현하는 형식입니다. 즉, 무엇을 계산하는 코드가 아니라 데이터를 어떤 모양으로 적을 것인가에 대한 약속입니다. 초보자가 이 둘을 프로그램처럼 느끼는 이유는 문법 모양이 낯설고, 파일로 따로 존재하는 경우가 많기 때문입니다. 하지만 본질은 계산이 아니라 표현입니다.

예를 들어 사용자 정보를 보내야 한다고 해 봅시다. 이름, 나이, 이메일 같은 값을 아무 규칙 없이 적으면 프로그램이 읽기 어렵습니다. 그래서 사람과 프로그램이 모두 이해하기 쉬운 모양으로 정리한 것이 JSON이나 XML입니다. 즉, 둘은 데이터를 안전하고 일관되게 주고받기 위한 포장 방식에 가깝습니다.

## JSON과 XML은 어떻게 다르게 생겼나요

JSON은 키와 값의 짝으로 이루어진 구조가 중심입니다. 그래서 객체나 목록을 표현하기 편하고, 자바스크립트와도 잘 어울려 웹 개발에서 널리 쓰입니다.

```json

{

  "name": "Kim",

  "age": 28,

  "skills": ["JavaScript", "React"]

}

```

XML은 태그를 열고 닫는 구조가 중심입니다. HTML과 비슷한 느낌이라 처음 보면 익숙하기도 하지만, 길고 장황해질 수 있습니다. 대신 구조와 메타데이터를 풍부하게 표현하기에 유리한 경우가 있어 특정 산업, 문서 교환, 오래된 시스템에서는 여전히 사용됩니다.

```xml

<user>

  <name>Kim</name>

  <age>28</age>

  <skills>

    <skill>JavaScript</skill>

    <skill>React</skill>

  </skills>

</user>

```

## 왜 요즘은 JSON을 더 자주 보게 되나요

웹과 앱 개발에서는 JSON이 더 간단하고 읽기 쉬운 편이라 자주 선택됩니다. 프론트엔드와 백엔드가 데이터를 주고받을 때도 JSON이 자연스럽고, 언어마다 파싱 도구도 잘 갖춰져 있습니다. 그래서 초보자가 처음 접하는 API 응답은 대부분 JSON인 경우가 많습니다.

그렇다고 XML이 사라진 것은 아닙니다. 금융, 공공, 문서 표준, 설정 파일, 오래된 엔터프라이즈 시스템에서는 XML이 아직도 중요한 역할을 합니다. 즉, JSON이 현재의 주류라고 해서 XML이 틀린 방식인 것은 아닙니다. 각각 강한 장면이 다릅니다.

## 초보자는 여기서 무엇을 기억하면 좋을까요

가장 먼저 기억할 것은 둘 다 데이터를 담는 형식이라는 점입니다. 계산을 하는 프로그램이 아니라, 데이터를 전달하고 저장하는 언어에 가깝습니다. 그다음으로는 JSON은 보통 더 가볍고 웹 친화적이며, XML은 구조 표현이 더 장황하지만 특정 분야에서 강하다 정도의 감각이면 충분합니다.

나중에 API 응답이나 설정 파일을 볼 때 이 감각이 매우 중요해집니다. 낯선 괄호나 태그를 보고 겁먹는 대신, 아, 이건 프로그램이 아니라 데이터를 적어 둔 형식이구나라고 이해하면 읽는 부담이 크게 줄어듭니다.

## 데이터 형식을 읽을 때 먼저 보는 점

XML과 JSON을 볼 때는 생김새보다 구조를 먼저 읽는 습관이 중요합니다. 데이터가 목록인지, 객체인지, 중첩이 깊은지, 이름표가 무엇인지 먼저 보면 형식이 달라도 겁이 덜 납니다. JSON은 웹 개발에서 가볍고 읽기 쉬워 널리 쓰이고, XML은 문서성, 확장성, 규격성이 중요한 곳에서 여전히 쓰입니다. 중요한 것은 형식의 유명세보다 어떤 시스템과 도구가 그 형식을 전제로 움직이느냐입니다.

정리하면, XML과 JSON은 프로그램이 아니라 데이터를 표현하는 형식입니다. JSON은 비교적 가볍고 웹에서 널리 쓰이며, XML은 태그 기반 구조 표현에 강해 특정 분야에서 계속 쓰입니다. 둘의 차이를 알면 API 응답, 설정 파일, 데이터 교환 문서를 훨씬 덜 낯설게 읽을 수 있습니다.
