# 멀티 스레드를 활용한 동시 수행

스레드는 한 프로세스 안에서 실제 작업 흐름을 실행하는 단위입니다. 멀티 스레드는 그 하나의 프로세스 안에서 여러 작업 흐름을 동시에 또는 번갈아 수행하게 만드는 방식입니다. 초보자가 자주 헷갈리는 지점은 프로세스와 스레드가 비슷해 보인다는 점인데, 핵심은 스레드가 같은 프로세스의 자원을 공유한다는 데 있습니다.

예를 들어 채팅 프로그램을 생각해 보면, 화면을 그리는 일, 네트워크 메시지를 기다리는 일, 파일 업로드 진행률을 보여 주는 일이 한 앱 안에서 동시에 돌아가야 할 수 있습니다. 이런 작업을 모두 한 흐름에서만 처리하면 특정 작업이 오래 걸릴 때 전체가 멈춘 것처럼 느껴질 수 있습니다. 멀티 스레드는 이런 응답성 문제를 줄이는 데 도움을 줍니다.

## 왜 멀티 스레드를 쓰나요

첫째는 응답성을 높이기 위해서입니다. 사용자 화면을 담당하는 스레드와 오래 걸리는 작업을 담당하는 스레드를 나누면, 파일 업로드 중에도 화면이 덜 멈춘 것처럼 만들 수 있습니다. 둘째는 자원을 더 효율적으로 쓰기 위해서입니다. 멀티코어 환경에서는 여러 스레드가 실제로 병렬 실행되며 처리량을 높일 수 있습니다.

셋째는 같은 프로세스 안에서 데이터를 공유하기 쉽기 때문입니다. 프로세스를 여러 개 띄우는 것보다 스레드를 나누는 편이 메모리 공유가 자연스럽고 생성 비용도 적은 경우가 많습니다. 그래서 서버 프로그램이나 게임 엔진, 백그라운드 작업이 많은 앱에서 멀티 스레드가 자주 등장합니다.

## 그런데 왜 멀티 스레드가 어렵다고 하나요

이유는 공유 때문입니다. 같은 메모리를 함께 쓰면 협력도 쉬워지지만 충돌도 쉬워집니다. 한 스레드가 값을 바꾸는 동안 다른 스레드가 동시에 읽거나 바꾸면 예상하지 못한 오류가 생길 수 있습니다. 이를 경쟁 상태라고 부르며, 디버깅이 특히 어렵습니다.

또한 스레드가 서로 자원을 기다리다 멈춰 버리는 교착 상태, 순서에 따라 결과가 달라지는 문제도 생길 수 있습니다. 그래서 멀티 스레드는 빠르기만 한 기술이 아니라, 올바른 동기화 설계가 함께 필요합니다. 초보자는 멀티 스레드를 쓰면 무조건 성능이 좋아진다고 생각하기 쉽지만, 잘못 쓰면 오히려 더 느리고 불안정해질 수 있습니다.

## 초보자는 어떤 기준으로 접근하면 좋을까요

먼저 모든 프로그램이 멀티 스레드를 꼭 써야 하는 것은 아니라는 점을 기억하면 좋습니다. 독립적인 작업이 있고, 응답성을 지켜야 하며, 공유 자원 접근을 잘 통제할 수 있을 때 멀티 스레드의 이점이 커집니다. 반면 단순한 순차 작업을 괜히 여러 스레드로 쪼개면 복잡성만 증가할 수 있습니다.

결국 멀티 스레드는 동시에 많이 한다기보다, 작업을 더 잘 나누고 시스템 자원을 더 잘 활용하기 위한 도구입니다. 그 장점과 위험을 함께 이해하는 것이 중요합니다.

## 핵심만 다시 정리하면

멀티 스레드는 하나의 프로세스 안에서 여러 실행 흐름을 활용해 응답성과 처리량을 높이려는 방식입니다. 같은 메모리를 공유하므로 효율적이지만, 경쟁 상태와 교착 상태 같은 동시성 문제도 함께 생깁니다. 따라서 멀티 스레드는 성능 도구이면서 동시에 설계 책임을 요구하는 기술입니다.

## 현업 장면으로 바꾸면 이렇게 보입니다

이 개념을 배우는 이유는 단어를 하나 더 외우기 위해서가 아닙니다. 메모리 부족, 충돌, 동시성 문제를 해석할 때 무엇을 먼저 볼지 정하는 눈을 만들기 위해서입니다.

결국 이 개념을 이해한다는 것은 운영체제가 왜 개발자의 관심사인지 납득하게 됩니다

## 여기서 많이 생기는 오해

이 개념이 갑자기 어려워지는 순간은 보통 운영체제와 하드웨어 이야기를 언어 문법과 별개인 어려운 이론으로만 보는 점입니다.

코드가 결국 CPU, 메모리, 저장장치, 운영체제를 지나 실행된다는 흐름을 붙잡으면 개별 용어가 훨씬 쉬워집니다. 그러면 비슷한 용어를 만나도 같은 상자에 모두 넣어 버리는 실수를 줄일 수 있습니다.

## 읽고 끝내지 않으려면 이렇게 해 보세요

이 개념을 내 것으로 만드는 가장 빠른 방법은 작은 실험입니다. 거창한 프로젝트가 아니라도 괜찮습니다.

1. 작업 관리자나 리소스 모니터를 열고 이 주제와 관련된 정보가 어디에서 보이는지 찾아봅니다.

2. 프로그램 하나를 실행하고 메모리 사용량, 프로세스 수, CPU 사용량이 어떻게 바뀌는지 관찰해 봅니다.

3. 느려짐이나 멈춤이 생겼을 때 코드 문제인지 실행 환경 문제인지 구분하는 질문을 세 개 적어 봅니다.

## 이 절을 단독 지식으로 두지 않는 방법

이 개념을 이해해 두면 뒤쪽 장을 읽을 때 새 용어가 나와도 덜 위압적으로 느껴집니다. 실제로 7장의 데이터 처리 성능, 8장의 네트워크 처리, 10장의 컨테이너와 인프라 운영에서 같은 기준이 다시 필요합니다.

결국 이 절의 목적은 지식을 하나 더 추가하는 것이 아니라, 다음에 나올 개념의 자리를 미리 만들어 두는 데 있습니다.
