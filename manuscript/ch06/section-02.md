# 컴퓨터는 어떤 구성 요소로 되어 있나요?

컴퓨터를 이해하는 가장 쉬운 방법은 하나의 똑똑한 상자로 보는 대신 역할이 다른 부품들의 협업으로 보는 것입니다. 우리가 작성한 프로그램은 결국 여러 하드웨어 요소를 거치며 실행됩니다. 그래서 CPU, 메모리, 저장장치, 입력 장치, 출력 장치, 네트워크 장치가 각각 무슨 일을 하는지 알면 프로그램이 느려지거나 멈추는 이유를 훨씬 현실적으로 이해할 수 있습니다.

가장 중심에는 CPU가 있습니다. CPU는 명령을 읽고 계산하고 제어하는 부품입니다. 흔히 컴퓨터의 두뇌라고 부르지만, CPU 혼자 모든 것을 해결하는 것은 아닙니다. 계산은 빠르지만 저장 공간은 거의 없고, 필요한 데이터를 메모리와 저장장치에서 계속 받아와야 합니다.

## 메모리와 저장장치는 무엇이 다를까요

메모리는 지금 실행 중인 프로그램이 바로 사용해야 하는 데이터를 잠시 올려 두는 작업대입니다. 빠르지만 비싸고 용량이 한정되어 있습니다. 전원이 꺼지면 일반적으로 내용도 사라집니다. 반면 저장장치는 파일과 프로그램을 오래 보관하는 창고에 가깝습니다. SSD나 HDD가 대표적이며, 메모리보다 느리지만 훨씬 많은 데이터를 저장할 수 있습니다.

이 차이를 이해하면 왜 프로그램 실행 전에 디스크에 있던 파일이 메모리로 올라오는지 자연스럽게 보입니다. 저장장치는 오래 보관하는 곳, 메모리는 지금 당장 일하는 곳이라는 감각이 중요합니다.

## 나머지 부품들은 어떤 역할을 하나요

입력 장치는 키보드, 마우스, 카메라, 센서처럼 컴퓨터에 정보를 넣는 통로입니다. 출력 장치는 모니터, 스피커, 프린터처럼 결과를 보여 주는 통로입니다. 네트워크 장치는 다른 컴퓨터와 데이터를 주고받는 길을 담당합니다. 또한 각 부품을 서로 연결하고 데이터가 오갈 수 있게 해 주는 통로 개념으로 버스를 이해하면 좋습니다. 이름이 생소해도 본질은 부품 간 이동 경로입니다.

최근에는 GPU도 중요한 역할을 맡습니다. 원래는 그래픽 처리에 강한 장치였지만, 대량의 병렬 계산에 유리해 머신러닝과 영상 처리에서도 널리 쓰입니다. 즉, 현대 컴퓨터는 CPU 하나가 전부 하는 구조가 아니라, 역할별로 특화된 장치들이 함께 일하는 구조입니다.

## 초보자는 어떤 그림을 떠올리면 좋을까요

한 문장으로 정리하면 이렇습니다. CPU는 계산하고, 메모리는 지금 필요한 것을 가까이 두고, 저장장치는 오래 보관하고, 입출력 장치는 바깥세상과 연결하고, 운영체제는 이 모든 자원을 조정합니다. 이 그림만 머릿속에 있어도 이후에 나올 메모리 부족, I/O 지연, 프로세스 스케줄링, 캐시 같은 개념을 붙잡기가 훨씬 쉬워집니다.

즉, 컴퓨터는 하나의 마법 상자가 아니라 역할을 나눈 시스템입니다. 개발자는 이 분업 구조를 이해할수록 코드가 실제로 어디서 비용을 쓰는지 더 잘 판단할 수 있습니다.

## 핵심만 다시 정리하면

컴퓨터는 CPU, 메모리, 저장장치, 입출력 장치, 네트워크 장치 같은 서로 다른 역할의 부품으로 구성됩니다. CPU가 계산을 맡더라도 메모리와 저장장치, I/O 없이는 아무 일도 할 수 없습니다. 개발자가 이 구조를 이해하면 프로그램의 실행 흐름과 성능 문제를 훨씬 더 현실적으로 해석할 수 있습니다.

## 실제로 만들 때는 이런 선택으로 이어집니다

이 개념은 정의 하나로 끝나는 주제가 아니라, 실제 선택의 기준이 되는 개념입니다. 특히 프로세스와 스레드 중 어떤 실행 단위를 이해해야 하는지 정리할 때 이 절의 내용이 곧바로 판단 기준이 됩니다.

이 관점을 잡아 두면 멀티스레드와 메모리 이야기가 갑자기 튀어나와도 맥락을 놓치지 않습니다

## 초보자가 자주 섞어 보는 경계

초보자가 이 개념을 어렵게 느끼는 이유는 대개 운영체제와 하드웨어 이야기를 언어 문법과 별개인 어려운 이론으로만 보는 점입니다.

코드가 결국 CPU, 메모리, 저장장치, 운영체제를 지나 실행된다는 흐름을 붙잡으면 개별 용어가 훨씬 쉬워집니다. 정의를 통째로 외우기보다 경계를 먼저 세우는 편이 훨씬 오래 갑니다.

## 작게 실험해 보면 이해가 단단해집니다

이 개념은 실제 장면에 붙여 보는 순간 기억이 오래갑니다. 아래처럼 가볍게 확인해 보면 충분합니다.

1. 작업 관리자나 리소스 모니터를 열고 이 주제와 관련된 정보가 어디에서 보이는지 찾아봅니다.

2. 프로그램 하나를 실행하고 메모리 사용량, 프로세스 수, CPU 사용량이 어떻게 바뀌는지 관찰해 봅니다.

3. 느려짐이나 멈춤이 생겼을 때 코드 문제인지 실행 환경 문제인지 구분하는 질문을 세 개 적어 봅니다.
