# 여러 프로그램이 동시에 실행되는 원리는 무엇인가요?

우리는 음악을 들으면서 브라우저를 켜고, 메신저를 띄우고, 코드를 작성합니다. 겉으로 보면 모든 프로그램이 동시에 실행되는 것처럼 보입니다. 실제로는 운영체제가 CPU 시간을 아주 짧게 나누어 여러 작업에 번갈아 배정하면서 이런 착시를 만들어 냅니다. 이것이 멀티태스킹의 기본 감각입니다.

CPU 코어가 하나뿐인 환경에서는 진짜 물리적 동시 실행이 아니라 매우 빠른 교대 실행이 중심입니다. 운영체제는 어떤 작업을 잠깐 실행시키고, 다음 작업으로 바꾸고, 다시 돌아오는 과정을 매우 빠르게 반복합니다. 사용자는 그 속도가 충분히 빠르면 여러 프로그램이 동시에 도는 것처럼 느끼게 됩니다.

## 문맥 전환과 스케줄링은 무엇인가요

어떤 작업을 실행하다가 다른 작업으로 바꿀 때는 현재 상태를 저장하고, 다음 작업의 상태를 불러와야 합니다. 이를 문맥 전환이라고 부릅니다. 상태에는 어떤 명령까지 실행했는지, 어떤 값들을 쓰고 있었는지 같은 정보가 들어 있습니다. 운영체제는 이런 전환을 관리하면서 전체 시스템이 고르게 움직이도록 합니다.

스케줄링은 누구에게 CPU를 얼마나 줄지 정하는 일입니다. 대화형 프로그램은 사용자의 입력에 빨리 반응해야 하고, 백그라운드 작업은 조금 늦어도 괜찮을 수 있습니다. 운영체제는 우선순위, 대기 시간, 공정성 같은 요소를 고려해 CPU 시간을 분배합니다.

## 멀티코어 시대에는 무엇이 더해지나요

요즘 컴퓨터는 CPU 코어가 여러 개인 경우가 많아, 일부 작업은 실제로 동시에 실행될 수 있습니다. 하지만 그렇다고 해서 스케줄링 문제가 사라지는 것은 아닙니다. 어떤 코어에 어떤 작업을 보낼지, 공유 자원은 어떻게 보호할지, 동시에 실행되는 작업끼리 어떻게 간섭을 줄일지도 여전히 중요합니다.

즉, 여러 프로그램이 동시에 실행되는 느낌은 시분할과 스케줄링, 그리고 멀티코어 하드웨어가 함께 만든 결과입니다. 개발자는 이 구조를 이해할수록 왜 응답성 문제가 생기는지, 왜 백그라운드 작업이 전체 시스템을 느리게 만들 수 있는지 잘 파악하게 됩니다.

## 초보자는 무엇을 기억하면 좋을까요

핵심은 운영체제가 CPU를 빌려주는 관리자라는 점입니다. 프로그램이 많아질수록 운영체제는 누가 먼저 실행될지, 얼마나 오래 실행될지, 언제 멈추고 바꿀지를 계속 결정합니다. 그래서 프로그램을 작성할 때도 긴 작업을 한 번에 독점하지 않도록 설계하는 것이 중요합니다.

이 관점을 잡고 나면 다음 절의 운영체제 역할, 프로세스와 스레드 차이, 동시성 문제도 모두 하나의 흐름으로 이어집니다. 결국 동시에 실행된다는 말 뒤에는 언제나 운영체제의 자원 배분이 숨어 있습니다.

## 핵심만 다시 정리하면

여러 프로그램이 동시에 실행되는 것처럼 보이는 이유는 운영체제가 CPU 시간을 짧게 나누어 번갈아 배정하기 때문입니다. 이 과정에서 문맥 전환과 스케줄링이 핵심 역할을 합니다. 멀티코어 환경에서는 실제 동시 실행도 가능하지만, 여전히 운영체제의 조정이 필수입니다.

## 이 내용을 알면 어디서 덜 막히는가

이 개념을 이해하면 컴퓨터 구조, 운영체제, 메모리와 동시성와 관련된 질문을 훨씬 현실적으로 바라볼 수 있습니다. 실제로는 프로그램이 왜 느려지는지, 어디서 병목이 생기는지 추적할 때 이 개념이 다시 등장합니다.

그래서 이 절의 설명은 곧 디버깅할 때 코드만 보는 습관에서 한 단계 더 내려갈 수 있습니다

## 읽다가 흔들리는 지점

이 주제에서 가장 흔한 오해는 운영체제와 하드웨어 이야기를 언어 문법과 별개인 어려운 이론으로만 보는 점입니다.

코드가 결국 CPU, 메모리, 저장장치, 운영체제를 지나 실행된다는 흐름을 붙잡으면 개별 용어가 훨씬 쉬워집니다. 이 기준만 있어도 뒤 장에서 같은 말을 다시 만나도 훨씬 덜 흔들립니다.

## 손으로 확인해 보면 더 빨리 남습니다

이 개념은 읽는 것만으로는 쉽게 손에 잡히지 않습니다. 아주 작은 확인만 해도 본문이 훨씬 입체적으로 보입니다.

1. 작업 관리자나 리소스 모니터를 열고 이 주제와 관련된 정보가 어디에서 보이는지 찾아봅니다.

2. 프로그램 하나를 실행하고 메모리 사용량, 프로세스 수, CPU 사용량이 어떻게 바뀌는지 관찰해 봅니다.

3. 느려짐이나 멈춤이 생겼을 때 코드 문제인지 실행 환경 문제인지 구분하는 질문을 세 개 적어 봅니다.

## 책 전체 흐름 속에서의 자리

이 개념은 여기서 끝나는 개념이 아닙니다. 이 절에서 잡은 감각은 7장의 데이터 처리 성능, 8장의 네트워크 처리, 10장의 컨테이너와 인프라 운영로 이어집니다.

따라서 다음 절을 읽을 때는 "이 개념이 지금 설명하는 층은 어디인가"를 계속 추적해 보세요. 그 습관이 전체 책을 훨씬 쉽게 만듭니다.
