# 컴퓨터 전공자들은 어떤 것들을 배우나요?

개발을 처음 배우는 사람은 종종 이렇게 생각합니다. "전공자는 코딩을 많이 해봐서 잘하는 거겠지." 맞는 부분도 있지만, 그것만으로는 설명이 부족합니다. 컴퓨터 전공에서 배우는 것은 특정 언어 문법만이 아니라, 컴퓨터와 소프트웨어가 어떻게 움직이는지를 여러 층위에서 이해하는 방법입니다.

그래서 전공자들이 배우는 과목 이름을 보면 처음에는 서로 전혀 상관없어 보입니다. 프로그래밍, 자료구조, 알고리즘, 운영체제, 데이터베이스, 네트워크, 소프트웨어 공학, 수학 같은 과목이 한꺼번에 등장합니다. 초보자 눈에는 "왜 이렇게 이것저것 다 배워야 하지?"라는 생각이 드는 것이 자연스럽습니다.

## 왜 이렇게 넓게 배우는가

이유는 간단합니다. 실제 소프트웨어는 한 가지 지식만으로는 만들어지지 않기 때문입니다. 화면을 만드는 일만 해도 사용자의 입력을 처리해야 하고, 데이터를 정리해야 하며, 서버와 통신해야 하고, 느려지지 않게 만들어야 합니다. 로그인 기능 하나만 생각해도 화면, 데이터 저장, 보안, 네트워크, 오류 처리까지 다 연결됩니다.

즉, 전공 수업이 넓어 보이는 이유는 현실의 소프트웨어가 넓기 때문입니다. 학교는 학생에게 당장 하나의 앱을 빨리 만드는 법만 가르치기보다, 나중에 어떤 분야로 가더라도 기본 축을 이해할 수 있도록 뼈대를 먼저 심어 줍니다.

## 보통 어떤 내용을 배우나

먼저 프로그래밍 과목에서는 코드를 쓰는 법 자체를 배웁니다. 변수, 조건문, 반복문, 함수 같은 문법도 배우지만, 더 중요한 것은 문제를 단계로 나누어 표현하는 사고방식입니다.

그다음 자료구조와 알고리즘에서는 데이터를 어떻게 담고, 어떤 순서로 처리할지를 배웁니다. 자료구조는 데이터를 담는 그릇에 가깝고, 알고리즘은 그 데이터를 처리하는 절차에 가깝습니다. 예를 들어 학생 명단을 빠르게 찾는 문제와, 수천 개의 주문을 정렬하는 문제는 같은 코딩이어도 접근 방식이 달라집니다.

운영체제 과목에서는 프로그램이 실제 컴퓨터에서 어떻게 실행되는지를 배웁니다. 프로그램이 메모리를 어떻게 쓰는지, 여러 작업이 동시에 돌아가는 것처럼 보이는 이유가 무엇인지, 파일은 어떻게 관리되는지 같은 내용을 다룹니다. 운영체제는 눈에 잘 보이지 않지만, 모든 프로그램이 그 위에서 돌아가기 때문에 매우 중요합니다.

네트워크 과목에서는 컴퓨터끼리 어떻게 통신하는지 배웁니다. 인터넷에서 데이터를 주고받는 규칙, 서버와 클라이언트가 요청과 응답을 주고받는 방식, 여러 장비가 어떻게 연결되는지를 이해하게 됩니다. 웹 서비스를 만들 때 이 지식은 거의 필수로 연결됩니다.

데이터베이스 과목에서는 데이터를 어떻게 저장하고 꺼내고 관리할지를 다룹니다. 단순히 데이터를 적어 두는 것을 넘어, 중복을 줄이고, 원하는 정보를 빨리 찾고, 동시에 여러 사용자가 접근해도 문제가 생기지 않게 만드는 방법을 배웁니다.

소프트웨어 공학 과목에서는 개발을 혼자 취미로 하는 수준을 넘어, 팀으로 만들고 오래 유지하는 방법을 다룹니다. 테스트, 설계, 요구사항 정리, 협업, 버전 관리, 유지보수 같은 내용이 여기에 들어갑니다.

## 왜 비전공자에게도 이 지도가 중요한가

비전공자가 이 모든 과목을 학교처럼 순서대로 배울 필요는 없습니다. 하지만 이런 큰 분류가 있다는 사실은 꼭 알아두는 편이 좋습니다. 그래야 지금 내가 배우는 것이 어디에 속하는지, 다음에는 무엇을 배워야 하는지 감을 잡을 수 있기 때문입니다.

예를 들어 자바스크립트를 배우고 있는데 서버에서 데이터를 불러오는 부분에서 막혔다면, 그건 단순히 문법 문제가 아니라 네트워크와 데이터의 문제일 수 있습니다. SQL이 낯설다면 데이터베이스 영역의 기초가 비어 있을 가능성이 큽니다. 이런 식으로 막히는 지점을 이름 붙여 볼 수 있어야 학습이 훨씬 효율적이 됩니다.

## 전공자와 비전공자의 진짜 차이

전공자와 비전공자의 차이를 지나치게 신비롭게 볼 필요는 없습니다. 전공자는 보통 이 지식들을 학교 커리큘럼 안에서 체계적으로 먼저 접한 사람입니다. 비전공자는 같은 지식을 조금 더 흩어진 경로로 배우는 경우가 많습니다.

따라서 비전공자에게 필요한 것은 열등감이 아니라 지도입니다. "나는 전공자가 아니니까 안 돼"라고 생각하기보다, "전공자는 어떤 지도를 따라 배웠는가"를 먼저 보는 것이 훨씬 도움이 됩니다. 지금 여러분이 이 책에서 얻어야 하는 것도 바로 그 지도입니다.

## 입문자는 이 지도를 어떻게 써야 할까요

전공 지도를 처음 볼 때는 모든 과목을 동시에 시작하려 하지 않는 것이 중요합니다. 지금 하는 공부가 화면 쪽인지, 데이터 쪽인지, 실행 원리 쪽인지 이름 붙여 보세요. 그러면 막혔을 때 "나는 코딩을 못한다"가 아니라 "네트워크 개념이 비어 있구나"처럼 원인을 더 정확하게 볼 수 있습니다. 전공 커리큘럼의 가치는 암기 목록보다도 이런 분류 감각을 주는 데 있습니다.

정리하면, 컴퓨터 전공은 언어 학원이 아닙니다. 소프트웨어를 둘러싼 여러 층위를 이해하는 훈련에 가깝습니다. 그리고 그 여러 과목은 따로 노는 것이 아니라 실제 서비스 안에서 모두 연결됩니다. 비전공자도 이 큰 분류를 알고 배우기 시작하면 훨씬 덜 흔들리게 됩니다.
